A listener sends real sensor snapshots to your online account. It needs Python 3, internet access and a node code—not the Go engine.

Set this up with an AI agent ↗

Limits and cadence

  • Free: 3 devices. Premium: 12 devices.
  • Normal cadence: 300 seconds per node. Premium boosts cost 1 core for 10 minutes at 100 seconds per snapshot.
  • Use next_snapshot_in from accepted responses, or retry_after after HTTP 429. Give each device its own code.

1. Create a node

Sign in and open Nodes. Create a named device and save its code privately. In the standalone app, paste it into World → Link account; your name, email, plan and device details confirm the account.

2. Run one listener cycle

Store WB_NODE_TOKEN in your environment or a private local environment file first. Do not paste it into public scripts or logs.

curl -fsSL {{ site_url }}/download/wavebeast-node.py -o wavebeast-node.py
# WB_NODE_TOKEN is already set privately in this shell.
WB_SITE={{ site_url }} WB_ONCE=1 python3 wavebeast-node.py

The listener reads Wi-Fi via nmcli where available. Other operating systems may need a sensor adapter. Verify that the log reports real signals and a successful result; a zero exit code alone does not prove the server accepted it.

3. Keep it running

WB_SITE={{ site_url }} python3 -u wavebeast-node.py

For background operation, use a per-user service. Example Linux unit at ~/.config/systemd/user/wavebeast-node.service, assuming the script is at ~/.local/share/wavebeast-node/wavebeast-node.py:

[Unit]
Description=WaveBeasts listener
After=network-online.target

[Service]
EnvironmentFile=%h/.config/wavebeast-node/node.env
Environment=PYTHONUNBUFFERED=1
ExecStart=/usr/bin/python3 %h/.local/share/wavebeast-node/wavebeast-node.py
Restart=on-failure
RestartSec=15

[Install]
WantedBy=default.target

The environment file contains WB_SITE={{ site_url }} and your WB_NODE_TOKEN; restrict it to your user with mode 600. Confirm the Python path on your machine.

systemctl --user daemon-reload
systemctl --user enable --now wavebeast-node
systemctl --user status wavebeast-node
journalctl --user -u wavebeast-node -n 20 --no-pager
# Stop and disable:
systemctl --user disable --now wavebeast-node

User services may stop at logout unless lingering is configured. macOS uses launchd and Windows uses Task Scheduler; the AI setup prompt handles those differences.

Troubleshooting

ResultMeaning / action
200 / acceptedSuccess. A beast, resources or nothing are all valid outcomes.
403Invalid/revoked code. Generate a current code and relink.
429Wait for retry_after; do not increase submission speed.
Zero signalsCheck nmcli/sensor permissions or add a real adapter.
Connection failureCheck internet access and WB_SITE. The listener retries at its fallback interval.

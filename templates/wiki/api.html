Build your own scanner, companion, or collection viewer. WaveBeasts accepts generic signals and exposes account state over HTTP.

Two APIs

Local engine: http://127.0.0.1:8777. Read /capabilities, submit POST /scan, or inspect /collection. If configured, local mutations use X-WB-Token.

Online account: {{ site_url }}. Registered device codes authenticate with X-WB-Node-Token. These are different tokens. Create a node on the website; do not embed a user’s code in a public application build.

ScanBundle

{"schema":"wavebeast.scanbundle","v":1,"signals":[
  {"kind":"code","strength":1,"value":{"symbology":"manual","data":"A-REAL-CODE"}}
]}

Supply actual readings. A valid scan can return a beast, resources, or nothing. Handle HTTP 403 (code rejected), 402 (Premium required), 409 (action conflict), and 429 (wait before retrying). Prices, balances and account rolls are validated by the server.

For the standalone binary’s CLI, Android share intents and deep links, see the integration guide. The website wiki describes the current account features.

One selected host

Engine clients should read GET /host and show its host.kind and host.url prominently. GET /state returns beasts, currency, and items from that authority. Standard scan, catch, shop, inventory, collection, release and training routes follow the selected host. An unavailable host returns an error; it never falls back to a different wallet.

Account linking uses POST /node/config. Select a self-hosted engine with POST /host/config and {"kind":"engine","url":"http://host:8777","token":"optional engine token"}, or choose {"kind":"local"} for this engine’s own database. Existing local saves remain separate and intact. Use the same account or host in each client.

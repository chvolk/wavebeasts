Overview

WaveBeasts is a scan-to-creature collector. Your devices sense the invisible world around you — Wi-Fi, Bluetooth, RF, light, sound, motion — and each unique reading is distilled into a procedurally generated creature with real, server-verified rarity. Catch them, raise a Buddy, and trade & battle other trainers.

Local play and one sensor node are free forever. The online layer (trading, battles, the async ladder, Buddy, uploads, multi-node fleets) is Premium.

How it works

A scan bundles the signals a device can read into a ScanBundle and submits it. The server distills two numbers from it:

  • Entropy — how much genuine, varied information the reading carries.
  • Coherence (0.4–1.0) — whether the signals reinforce or cancel. Aligned signals reinforce; opposed phases, heavy motion, and saturated signals cancel.

The effective entropy that drives every roll is entropy × coherence — so more data is not a guaranteed win. Each scan resolves to one of three outcomes:

  • Beast — a creature appears. This needs an identity signal (QR > barcode > NFC > image features, or a derived identity from ambient Wi-Fi/sensors). Chance rises with entropy.
  • Resource — currency, food, or a drive (see below).
  • Nothing — even a good reading can collapse to nothing via destructive interference.

Stats are rolled server-side with a per-scan secret nonce, so they can't be predicted, modded, or ground out. The species is deterministic from the bundle; the individual is not.

Tribes & stats

Beasts have six stats: HP, ATK, DEF, SPD, SP, RES (base values 45–80). Each beast belongs to a tribe that biases two of those stats (+18):

Stats scale with level (1→100). XP to the next level is level³ × 15. Beasts evolve through 5 forms at levels 1 / 16 / 32 / 48 / 64, with stat multipliers 1.0 → 1.25 → 1.55 → 1.9 → 2.3.

Tribe passives (e.g. crit or damage perks) are defined but not yet applied in battle — they're coming in a later update.

Battle mechanics

Battles are 3-v-3 auto-battles (Super-Auto-Pets style) and are fully deterministic from a seed. Your team is up to three fighters; in a local scan your "party" is your three highest-level beasts.

  • Turn order: the higher SPD fighter acts first each round (ties favour the challenger's side). Up to 300 turns.
  • Move: a random damaging move; a beast with none uses Struggle (power 35).
  • Damage: ((2×level/5 + 2) × power × ATK / DEF) / 50 + 2, then modifiers below. Physical moves use ATK vs DEF; special moves use SP vs RES.
  • STAB ×1.5 when the move's type matches the attacker's type.
  • × type effectiveness (the chart above).
  • Crit: 6.25% chance for ×1.5 damage.
  • Spread: every hit rolls ×0.85–1.00. Minimum damage is 1.

A side wins when the other is wiped; at the turn cap the win goes to whoever has more total HP remaining (equal → draw). Battle on scan: once you have a party, a wild encounter has a 35% chance to challenge you — win and it's weakened and catchable; lose and it flees.

What nodes do

A node is any device signed in to your account that submits sensor snapshots to it. A node doesn't need the full engine — it just assembles a ScanBundle and POSTs it to {{ base }}/api/snapshot with its token. Run one on a phone, a Pi, or any PC.

  • Cadence: ~one snapshot per 60 s per node. The server's reply tells the node when it may submit again; submitting early returns 429 rate_limited.
  • Boosts (Premium): spend 1 core to drop a node to a 20 s cadence for 10 min.
  • Caps: 1 node on free, 12 on Premium. Give each device its own token.

Create tokens on the Nodes page — "Generate app token" for the mobile app, or "Add node" for anything else. Node creation is web-only (it's tied to your login); everything after is CLI.

Set up a node (CLI)

1 · Quick test (one snapshot)

curl -s -X POST {{ base }}/api/snapshot \
  -H "X-WB-Node-Token: YOUR_TOKEN" -H "Content-Type: application/json" \
  -d '{"schema":"wavebeast.scanbundle","v":1,"signals":[
        {"kind":"wifi","strength":0.7,"value":{"rssi":-50}},
        {"kind":"scalar","strength":0.6,"value":{"metric":"lux","n":300}}]}'

A {"accepted":true,...} reply means it worked. 429 = too soon, 403 = bad token.

2 · Persistent node (real sensors, on a timer)

The listener client is a single stdlib-only Python file — no dependencies. It reads nearby Wi-Fi (via nmcli) each cycle and posts on the server's cadence.

curl -fsSL {{ base }}/download/wavebeast-node.py -o wavebeast-node.py
WB_NODE_TOKEN=YOUR_TOKEN python3 wavebeast-node.py          # loops forever
WB_NODE_TOKEN=YOUR_TOKEN WB_ONCE=1 python3 wavebeast-node.py # single shot

Environment variables:

VarMeaning
WB_NODE_TOKENyour node token (required)
WB_SITEsite base URL (default {{ base }})
WB_INTERVALfallback seconds between snapshots (the server's reply overrides)
WB_ONCEset to send one snapshot and exit
WB_SIGNALS_CMDa command whose stdout is a JSON array of extra signals (see below)
WB_ENVIRON_URLa JSON endpoint of environment scalars to fold in

3 · Keep it running (systemd)

# /etc/systemd/system/wavebeast-node.service
[Unit]
Description=WaveBeast listener node
After=network-online.target

[Service]
Environment=WB_NODE_TOKEN=YOUR_TOKEN
ExecStart=/usr/bin/python3 %h/wavebeast-node.py
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target

Then: sudo systemctl enable --now wavebeast-node

Custom sensors

Point WB_SIGNALS_CMD at any command that prints a JSON array of signals to stdout — that's how you feed a node from a sensor the client doesn't know about. Each signal is an object:

{ "kind": "scalar", "strength": 0.0-1.0, "value": { "metric": "co2_ppm", "n": 812 } }

kind is a label (e.g. scalar, wifi, rf); strength is the signal's normalized intensity (0–1, drives entropy); value is any JSON payload. Example — a mmWave presence sensor:

export WB_SIGNALS_CMD='python3 -c "import json,random; print(json.dumps([{\"kind\":\"scalar\",\"strength\":round(random.random(),2),\"value\":{\"metric\":\"mmwave_motion\",\"n\":random.randint(0,100)}}]))"'

Each device is capped at 10 custom sensor values per snapshot — enough to be expressive, not enough to fabricate infinite entropy.
